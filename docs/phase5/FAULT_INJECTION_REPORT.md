## 1. 新增：安装器（19 例）

| 注入 | 预期 | 实际 | 结果 |
| --- | --- | --- | --- |
| 归档路径 `/etc/passwd` / `../x` / `x/../y` | 拒绝 | 写侧抛错 | ✅ |
| 归档头部被改成 `../evil.txt`（绕过写侧） | 读侧拒绝 | `escapes root` | ✅ |
| 非 gzip 包 | 拒绝 | `not a gzip` | ✅ |
| 包内容被篡改 | 校验失败 | `hash mismatch` | ✅ |
| 父路径被普通文件占位 | 前置检查 FAIL | `blocked=true` | ✅ |
| 目标目录属于别的产品 | 拒绝安装 | FAILED 状态 | ✅ |
| 上次安装未完成（状态文件） | WARN 且可继续 | `unfinished_install=WARN` | ✅ |
| 后置检查失败 | 回滚到旧版本 | `ROLLBACK_COMPLETED` + 内容恢复 | ✅ |
| 回滚时备份被删除 | 明确失败 | `ROLLBACK_FAILED` + error 有内容 | ✅ |
| 安装中途抛错 | 无半安装残留 | 无目录、无 staging、状态可读 | ✅ |
| 损坏包（截断） | 校验阶段拒绝 | 未创建安装目录 | ✅ |
| 重复安装 | 幂等 | `idempotent=true`，无新备份 | ✅ |
| 重装/卸载 | 保留用户数据 | 文件仍在 | ✅ |

**未覆盖**：ENOSPC、只读挂载、真实 SIGKILL、双安装器竞争。

## 5. 逐项"是否需要人工恢复"

| 故障 | 自动恢复 | 人工介入 |
| --- | --- | --- |
| 安装后置检查失败 | ✅ 回滚到旧版本 | 否 |
| 安装回滚失败（备份丢失） | ❌ `ROLLBACK_FAILED` | **是**（需从外部备份恢复） |
| 恢复冲突（阻止） | ✅ 不动文件 | 否（用户决定是否 force） |
| 恢复失败 | ✅ 回滚到恢复前 | 否 |
| 恢复回滚失败 | ❌ `rolledBack=false` | **是** |
| 锁 STALE | ✅ 回收并留痕 | 否 |
| 锁损坏 | ❌ `RECOVERY_REQUIRED` | **是**（人工确认后删锁目录） |
| 插件崩溃/超时 | ✅ 标记 + kill | 否 |
| 策略哈希不符 | ❌ 拒绝加载 | **是**（检查策略文件或从备份恢复） |

## 6. 结论

Phase 5 的故障注入从"数据层"延伸到"交付层 / 进程间层 / 权限层"。
仍有三类故障会让系统停在需要人工介入的状态（回滚失败、锁损坏、策略被篡改）——这是**有意设计**：宁可停下并报告，也不静默放行。
