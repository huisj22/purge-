# 原项目安全评审（ORIGINAL_SECURITY_REVIEW）

对象：`dsh-purge-community@1.6.91` + 一键安装包
方法：代码阅读（证据见 `evidence/`）+ 本机只读测绘 + 对安装包脚本的静态复核
结论用途：确定 Purge+ 的继承边界（MASTER PROMPT §07）

---

## 1. 原项目的实际作用机制

它做的不是「给 Agent 加功能」，而是**改写宿主源码来移除宿主的安全闸门**。86 条补丁按层可分为：

| 层 | 条数 | 典型内容 | 效果 |
| --- | --- | --- | --- |
| 提示词改写 | 27 | 去宿主身份、去审批句、去沙箱提示、去计划模式限制 | 模型不再看到「需要确认」的措辞 |
| 代码改写 | 47 | 审批策略默认 `never`、自动放行、fs 围栏关闭、sandbox 透传、escalation 无条件授予 | 宿主真的不再询问/不再拦截 |
| 工具面改写 | 9 | 文件读写上限提高、子代理深度提高、提问等待压缩 | 单次操作能力扩大 |
| 兼容层 | 3 | settings 旧 API、会话别名 | 让上述改写在旧宿主也能生效 |

配合：`danger-full-access` 权限预设、`approval: never`、`hooksDenyBypass: true`（默认开）。

**这是它的产品定位，不是漏洞。** 问题不在「它做了这件事」，而在于：**这些改写没有任何风险分级、没有来源证明、没有可视化的影响面**，用户只知道「点了应用」。

## 2. 安全风险清单（按可利用性排序）

| # | 风险 | 证据 | 影响 | 严重度 |
| --- | --- | --- | --- | --- |

| R4 | **备份可被不可逆覆盖**：三处先删既有 `.bak` 再重建 | `extract-asar.js:200-203`、`desktop.js:1043`、`restart-desktop.js:280-283` | 回滚源被自己毁掉，事故不可逆 | 高 |

| R7 | **更新供应链单点**：镜像可传包，token 虽不发镜像但摘要校验在未配镜像时跳过交叉校验 | `community.js:904`、`update-http.js:173` | 镜像被劫持时缺第二来源证明 | 中 |
| R8 | **静默失效的迁移代码**（`ReferenceError` 被 `catch{}` 吞） | `redteam/schema.js:586,591` | 安全相关字段回填永久缺失且无人知 | 中 |
| R9 | **锚点漂移 + expect 缺失**：宿主升级后可能把替换应用到相似但错误的代码段 | `core.js:3457-3462`（仅 1 条用 expect） | 可能改坏无关逻辑，且难以察觉 | 中 |
| R10 | **失败被软通过**：47 条 optional + `skipped` 都算 ready | `core/verify.mjs:89-99,197-204` | 面板假绿，用户误判为已生效 | 中 |
| R11 | **`yaml` 顶层硬依赖**：引导阶段无 node_modules 即崩 | `permission-state.js:1` | 安装不可用（1.6.11 曾因此撤回） | 低（可用性） |
| R12 | **演练台技能可写本机与网络**，无执行沙箱 | `skills/redteam/*`、`redteam/tools.js` | 误用成本由用户承担 | 低（需用户主动） |

## 3. 边界判定（MASTER PROMPT §07 逐条落实）

§07 要求：不得把开发目标设定为「移除模型安全机制 / 绕过安全审批 / 解除安全约束 / 让 Agent 无条件执行高风险操作」。据此：

| §07 条目 | 原项目对应 | Purge+ 处置 |
| --- | --- | --- |
| ①在功能矩阵中识别 | — | 已完成：矩阵 A1-A13、B1-B11 逐条登记，标注「效果」列 |
| ②记录原始目的 | — | 目的：在用户自有机器的本地环境里做教学/实验，减少交互摩擦 |
| ③评估安全风险 | — | 本文 §2 的 R1-R12；最高风险是「无鉴权写入口」与「静默全权」 |
| ④保留合法工程能力（配置/状态/审计/兼容/恢复） | core/selfcheck/audit/snapshot | **全部保留并重构**：补丁引擎→Pack 引擎、25 层自检→规则化诊断、jsonl 审计→哈希链、快照→事务 |
| ⑤设计安全可审计的替代 | — | 见 §4 |
| ⑥不升级为更强的绕过机制 | — | **Purge+ 不内置任何绕过审批/沙箱/模型安全的规则**；不提供「一键全开」；不新增提权、免检测、隐蔽化能力 |

**被移除的能力（REMOVE）**：拒绝检测重试（B7，属对模型输出的干预且副作用不可观测）。

## 4. Purge+ 的替代设计

| 原能力 | 替代物 | 安全增量 |
| --- | --- | --- |
| 86 条补丁硬编码在插件里 | **Modification Pack**：外部数据文件 + 风险分级 + 来源哈希 | 用户能看到「这个包会改什么、风险几级、来自哪」 |
| 点「应用」即写宿主 | `plan()` 只读预览 → `apply()` 走**事务**（快照→写→回读校验→提交/回滚） | 半完成状态在结构上不可能 |
| 无鉴权 HTTP | 全端点同源 + 变更类端点要求 `confirm` + 策略层判定 + 审计链 | R1 消除 |
| 静默全权预设 | 不提供全权预设；风险 ≥70 直接 deny，30-69 需显式确认 | R2 消除 |
| jsonl 审计 | SQLite 哈希链（seq/prev_hash 连续，断链即 broken） | 审计不可静默篡改 |
| 安装器先杀后验 | `install --verify-first`：先验证再允许任何关闭动作 | R3 消除 |
| `.bak` 覆盖式备份 | 内容寻址对象库 + 唯一快照 ID + `verify()` | R4 消除 |
| optional/skipped 算绿 | 单一聚合口径：`unknown` 永远黄，只有 evidence 才 ok | R10 消除 |

**Purge+ 明确不做的事**

1. 不生成、不内置、不推荐任何「关闭审批/沙箱/提示词闸门」的 pack 内容；这类 pack 只能由用户自行导入，导入时被风险评分与审计记录。
2. 不自动重启或关闭用户进程（v0.1 无换包能力）。
3. 不提供无条件执行、免确认、免审计的执行路径。
4. 不做隐蔽化（不隐藏文件、不篡改检测、不留后门的「无痕模式」）。

## 6. 残余风险与缓解

| 残余风险 | 缓解 |
| --- | --- |
| 用户自行导入高风险 pack | 导入即评分 + 强制 `plan` 预览 + 审计链 + 一键回滚；包内规则永不自动执行 |
| 宿主升级导致漂移 | 漂移是显式异常状态（不是 skipped），并在 UI 标红 |
| 本机 API 被同源脚本滥用 | 默认只绑 `127.0.0.1`；变更类端点需 `confirm`；审计留痕 |
| 平台自身被插件越权调用 | 插件清单声明 capabilities，越权抛 `CapabilityError` |
| AI 建议被当成指令 | AI 只能产出 `proposedAction`，必须过确定性策略；建议标注「已验证/推断/建议」 |
